STEP 5 — INITIAL DOMAIN RULES
==================================================

Implement these foundational domain rules in reusable services, not directly inside route handlers.

SURPLUS:

netSurplusKwh =
generationKwh - consumptionKwh

marketableSurplusKwh =
max(netSurplusKwh, 0)

A user must not be able to list negative energy.

A user must not create a listing against a solar system they do not own.

A listing cannot be created with an invalid availability range.

A user must not be able to trade with themselves.

Energy must not be accidentally allocated multiple times.

GRID DECISION:

APPROVED
ADJUSTED
RESTRICTED

Initial deterministic thresholds may be used for the prototype, but they must live inside a dedicated GridDecisionService/configuration rather than being scattered through controllers.

MATCHING:

Matching must eventually consider multiple factors including:

- price
- availability
- quantity fit
- proximity
- reliability
- grid suitability

Do NOT implement marketplace ranking as simply "cheapest seller wins."

PRICING:

The pricing architecture must eventually support:

- supply
- demand
- market conditions
- grid conditions/congestion

For this phase, create interfaces/domain boundaries so the deterministic pricing engine can be implemented cleanly in the next phase.
